# Smart Pantry Manager

A Java Android app that helps households cut food waste. You record the ingredients you already have at home, and the app suggests recipes you can cook **using strictly those ingredients** - a recipe is only suggested when every single ingredient it needs is in your pantry in at least the required quantity.

Built for **Mobile App Development 700** (Richfield Graduate Institute of Technology).

## Features

- **Pantry management (full CRUD)** - add, view, edit and delete pantry items with a name, quantity, unit and optional expiry date.
- **Pantry list** - a `RecyclerView` with a custom `PantryAdapter`, bound to the SQLite database.
- **20 seeded recipes** - South African home cooking (pap, chakalaka, bobotie, umngqusho, malva pudding and more), loaded automatically on first run.
- **Suggested Recipes** - runs the strict-matching rule against the current pantry every time the screen opens.
- **"Almost there" list (stretch goal)** - recipes missing exactly one ingredient, shown in a clearly separate section and never mixed into the suggestions.
- **Recipe detail** - full ingredient list (each marked as in-pantry or missing) and numbered method.
- **Settings** - expiring-soon alerts with a configurable warning window, show/hide the "Almost there" list, show quantities in base units, load a sample pantry, clear the pantry.
- **Empty states** - a clear message when the pantry is empty or when no recipe matches.
- **Input validation** - inline errors for missing or invalid names, quantities and past expiry dates.

## Strict-matching rule

`RecipeMatcher` checks every required ingredient of every recipe:

1. Ingredient names are normalised by `IngredientNormaliser` (lower case, descriptors such as "fresh" or "chopped" removed, plurals reduced to singular, local synonyms mapped - e.g. "Mealie meal" = "maize meal", "Tomatoes" = "tomato").
2. Quantities are converted by `UnitConverter` to a base unit (g, ml or pieces). kg/g, L/ml, tsp/tbsp/cup are converted directly; known densities and average piece weights allow safe conversions such as "1 kg potatoes" against "4 potatoes".
3. Duplicate pantry entries of the same ingredient are added together.
4. If **any** ingredient is missing or short, the recipe is excluded from the suggestions.

## Database choice: SQLite (SQLiteOpenHelper)

SQLite was chosen because:

- The pantry is personal data for one user on one phone, so a local on-device database is the natural fit - no account, server or internet connection is needed.
- It works offline, which matters where mobile data is expensive.
- It is built into Android, so there is no extra hosting, cost or configuration.
- The data is relational (a recipe has many ingredients), which suits SQL tables with a foreign key.
- It matches the persistent-storage approach taught in the module.

Tables: `pantry_items`, `recipes`, `recipe_ingredients` (`recipe_id` references `recipes.id` with `ON DELETE CASCADE`). Settings are stored separately with `SharedPreferences`.

## Tech stack

| Item | Choice |
|---|---|
| Language | Java (all application code) |

## Setup and run

1. Install **Android Studio** (current stable release) with the Android SDK.
2. Clone the repository:
   ```
   git clone https://github.com/lerato-z/smart-pantry-manager.git
   ```
3. In Android Studio choose **File > Open** and select the `smart-pantry-manager` folder.
4. Wait for the Gradle sync to finish. If prompted, set the Gradle JDK to the bundled JetBrains Runtime (**Settings > Build, Execution, Deployment > Build Tools > Gradle**).
5. Create an emulator in **Device Manager** (e.g. Pixel 7, API 34 or 35) or connect an Android phone with USB debugging on.
6. Press **Run** (Shift + F10).
7. Optional: open **Settings > Load sample pantry** to fill the pantry with demo ingredients.

To run the unit tests, right-click `app/src/test/java` and choose **Run 'Tests in ...'**.
